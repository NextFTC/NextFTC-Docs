<Aside type='danger'>
    Installing NextFTC v2 in a project that already has NextFTC v1 will work,
    but run into errors at build-time, as the libraries contain classes with the same name.

    It is recommended to remove NextFTC v1 from your project and follow the migration guide (coming soon).

</Aside>

To install NextFTC in an FTC robot project, open `TeamCode/build.gradle`,
and add **one** of the following to your `dependencies` block:

<NextFTCDependencies />

You only need the last module you plan to use, because each one pulls its dependencies:

- `robot` includes `hardware` and `control`.
- `hardware` includes `control`.
- `control` includes the `units` and `linalg` helper libraries.

For most robot projects, that means adding only `robot`.

If you are using the hardware and/or robot modules,
add the following to the `repositories` block to allow Gradle to find the necessary dependencies.

```groovy
maven {
    url 'https://repo.dairy.foundation/releases'
}
```

## Snapshots

Snapshots are builds of the latest unreleased code for testing and iteration.
Features added in snapshot versions may not work as expected
and may also change in between snapshot builds.
API documentation for snapshot versions can be found at
[kdoc.nextftc.dev/snapshot](https://kdoc.nextftc.dev/snapshot).

<Aside type="caution">
  Snapshots can change or break without warning. Do not use a snapshot build of
  NextFTC at competitions without testing first.
</Aside>

Add the Maven Central snapshots repository to the `repositories` block:

```groovy
maven {
    url 'https://central.sonatype.com/repository/maven-snapshots/'
}
```

Then use a snapshot version _instead of_ the release dependency
(there should only be one `dev.nextftc.v2:robot` dependency):
